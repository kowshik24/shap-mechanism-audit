\begin{abstract}
Post-hoc explanation methods such as SHAP are routinely applied to predictive-maintenance
classifiers, but the resulting attributions are rarely checked against anything beyond the
analyst's intuition. We use a property of the AI4I~2020 predictive maintenance dataset that is
usually discarded: its binary \texttt{Machine failure} label is the logical OR of five
independently defined failure mechanisms (tool wear, heat dissipation, power, overstrain, and a
random failure with no physical cause), each with an exact, published triggering rule. We train an
imbalance-aware gradient-boosted classifier on the composite label only -- withholding the five
sub-labels from the feature set entirely -- and then use the sub-labels purely as a post-hoc audit:
for each mechanism, we measure the share of the model's mean absolute SHAP attribution, on the rows
where that mechanism fired, that falls on the features the mechanism's trigger depends on, and test
it against a model-randomization null built from models retrained on permuted labels. We show that
a naive null (random subsets of failure rows under the same model) is inadequate: a model trained
on permuted labels passes it, because mechanism rows are atypical in their own features. Under the
model-randomization null, our tuned XGBoost model (precision~1.00, recall~0.82, F1~0.90 on the
held-out failure class) passes all four physical mechanisms ($p \le 0.02$), while a label-permuted
model fails all four and a model given a spurious shortcut sensor fails exactly the mechanism the
shortcut mimics -- despite that model's accuracy staying competitive. The result holds on rows where
exactly one mechanism fired, and three of four mechanisms remain clearly recoverable from raw sensor
features alone. We argue this protocol -- a dataset's own latent causal substructure used as a
faithfulness probe -- applies to any predictive-maintenance setting where a coarse target aggregates
several distinct, partially-labeled failure modes.
\end{abstract}

\section{Introduction}

Predictive maintenance (PdM) models are increasingly built with gradient-boosted trees or neural
networks and explained after the fact with SHAP \citep{lundberg2017shap}. The explanation is
typically presented as evidence that the model ``makes sense'' -- a beeswarm plot, a bar chart of
global feature importance -- but is rarely checked against an independent source of truth about
\emph{why} the underlying process actually failed. This is a meaningful gap: a model can achieve
strong discriminative performance while keying off a spurious correlate of failure rather than the
mechanism itself, and a plausible-looking SHAP plot will not by itself reveal the difference
\citep{cummins2024survey}.

The AI4I~2020 dataset \citep{matzka2020explainable} offers an unusual opportunity to close this gap
without constructing anything artificial for the purpose. Its target, \texttt{Machine failure}, is
by design the logical OR of five independent sub-conditions -- tool wear failure (TWF), heat
dissipation failure (HDF), power failure (PWF), overstrain failure (OSF), and a random failure
(RNF) that fires with fixed probability regardless of process state. Each of the first four has an
exact, published closed-form trigger (Table~\ref{tab:mechanisms}); RNF has none. Critically, a model
trained to predict \texttt{Machine failure} is never given these five labels -- it only ever sees
the OR of them. This mirrors deployments in which a single ``needs maintenance'' flag aggregates
several distinct root causes that are recorded separately, or not at all, and never reach the model
as a training signal.

This gives us a natural faithfulness probe: after training on the composite label alone, we can go
back and ask, for the subset of rows where a specific mechanism actually fired, whether the model's
SHAP attributions concentrate on the feature that mechanism's own definition implicates. If they do
not, that is a warning sign that the classifier is exploiting a different, possibly spurious,
correlate. An audit is only meaningful if it can fail, so we also construct models it
\emph{should} reject -- one trained on permuted labels, one given a spurious shortcut sensor --
following the model-randomization logic of \citet{adebayo2018sanity}.

\paragraph{Contributions.}
\begin{enumerate}
  \item An imbalance-aware benchmark of seven model families (Logistic Regression, SVM, $k$-NN,
    Decision Tree, Random Forest, XGBoost, and a small PyTorch MLP) on AI4I~2020, with a
    resampling-technique bake-off (SMOTE vs.\ Borderline-SMOTE vs.\ ADASYN), hyperparameter and
    decision-threshold tuning, and 5-fold cross-validation.
  \item A lightweight cross-checking protocol that uses a dataset's own latent, partially-labeled
    causal substructure -- rather than purpose-built synthetic ground truth -- to audit whether a
    trained model's SHAP explanations are faithful to the real generating mechanism, with a
    model-randomization null. We show the obvious alternative null is confounded and passes a
    model that learned nothing.
  \item Evidence the audit discriminates: the tuned model passes all four physical mechanisms; a
    label-permuted model fails all four; a model with an injected shortcut fails exactly the
    mechanism the shortcut mimics while its accuracy stays competitive. We also report an
    exclusive-mode analysis and a raw-feature ablation addressing circularity.
\end{enumerate}

\section{Related Work}

\citet{matzka2020explainable} introduced the AI4I~2020 dataset alongside a LIME-based
illustration of local explanations for individual predictions, but did not systematically audit
attributions against the five sub-mechanisms across the dataset. Several subsequent works apply
SHAP to AI4I~2020 for global feature-importance reporting -- e.g., a recent milling-machine study
\citep{milling2025shap} reports SHAP summary plots for tree ensembles trained on this dataset --
but, to our knowledge, none of them cross-check per-mechanism attributions against the known
triggering rules, nor test whether such a check can fail. A recent
physics-informed benchmarking study \citep{physicsinformed2026} constructs engineered features from
the same sensor variables and reports a Random Forest positive-class F1 of 0.722 on AI4I~2020, and
a connected-vehicles study \citep{connectedvehicles2026} benchmarks LightGBM under a stricter
SMOTE-confined-to-training-folds cross-validation protocol, reporting macro-F1 $0.814 \pm 0.012$.
We compare directly against both in Section~\ref{sec:results}.

\citet{causalbenchmark2026} take a related but distinct angle: they build formal causal structural
models on a similarly-sized CNC failure dataset to optimize maintenance decisions under asymmetric
cost, and show causal features generalize better than raw correlational ones. Our goal is narrower
and complementary -- we do not build a causal model of the process; we audit whether an ordinary
correlational classifier's \emph{post-hoc explanation} happens to align with the true mechanism,
using labels that already encode that mechanism.

Work on faithfulness evaluation for explainability methods generally relies on \emph{synthetic}
ground truth: data is generated from a known functional form specifically so that the correct
attribution is computable in closed form \citep{liu2021synthetic}, or on randomization tests such
as \citet{adebayo2018sanity}, who show that some saliency methods produce near-identical
explanations for trained and randomized models. We borrow that randomization logic for our null.
Our approach differs in
where the ground truth comes from -- rather than designing a synthetic task for the purpose of
evaluating explanations, we reuse sub-labels that already exist in an otherwise ordinary,
publicly available PdM benchmark, aggregated away in the task the model is actually asked to solve.
AI4I~2020 is itself a simulated dataset generated from these same closed-form rules, a caveat we
return to in Section~\ref{sec:limitations}.

\section{Dataset}
\label{sec:dataset}

AI4I~2020 \citep{matzka2020explainable} contains 10{,}000 rows and 14 columns: a row identifier and
product ID (dropped), a categorical product quality variant (\texttt{Type} $\in \{L, M, H\}$, 50/30/20\%
of rows respectively), five continuous/integer process variables (air temperature, process
temperature, rotational speed, torque, tool wear), the composite \texttt{Machine failure} label, and
the five mechanism indicators of Table~\ref{tab:mechanisms}. \texttt{Machine failure} is 1 for 339
of 10{,}000 rows (3.39\%), a severe class imbalance typical of real PdM data.

The released labels are not perfectly consistent with the stated OR rule, and this matters for the
audit. 24 rows have more than one mechanism flag set; 9 failures have no mechanism flag at all; and
18 of the 19 RNF rows have \texttt{Machine failure}~$= 0$. The last point means the RNF subgroup is
almost entirely rows the model is supposed to classify as \emph{non}-failures, so it cannot serve as
a strong negative control on its own -- we still report it, but the discriminating evidence for the
audit comes from the positive controls in Section~\ref{sec:robustness}. We run the audit both on all
flagged rows and on rows where exactly one mechanism fired.

\section{Methodology}

\subsection{Feature engineering}
We construct four features directly from the mechanism definitions in Table~\ref{tab:mechanisms},
without using the mechanism labels themselves: \emph{Power} $=$ torque $\times$ rpm (rad/s) (mirrors
the PWF rule), \emph{Temp\_diff} $=$ process temperature $-$ air temperature (mirrors HDF),
\emph{Overstrain} $=$ tool wear $\times$ torque (mirrors OSF), and \emph{Overstrain\_ratio} $=$
Overstrain normalized by the type-specific limit. This gives the model, in principle, direct access
to each mechanism's driving quantity without ever seeing which mechanism fired.

\subsection{Leakage-safe feature extraction}
\texttt{UID} and \texttt{Product ID} are identifiers and are dropped. TWF, HDF, PWF, OSF, and RNF
are components of the target by construction ($\texttt{Machine failure} = \bigvee_i \text{mode}_i$)
and are excluded entirely from the feature matrix; they are retained only as held-out audit labels.

\subsection{Split, resampling, and models}
We use a stratified 70/20/10 train/validation/test split. The preprocessor (standard-scaling $+$
one-hot encoding) is fit on the training split only. We compare SMOTE \citep{chawla2002smote},
Borderline-SMOTE \citep{han2005borderline}, and ADASYN \citep{he2008adasyn} by resampling the
training split and scoring a fixed default XGBoost \citep{chen2016xgboost} on the untouched
validation split; the winner (Borderline-SMOTE in our run) is used for the remainder of the
pipeline. We train seven model families -- Logistic Regression, SVM (RBF), $k$-NN, Decision Tree,
Random Forest, XGBoost, and a small PyTorch feed-forward network -- on the resampled training data
and evaluate on the untouched, imbalanced validation and test splits.

\subsection{Tuning and validation}
Model selection uses the validation split only: XGBoost has the highest validation F1 (0.826,
against 0.739 for the runner-up, Random Forest) and is the only model tuned further. Tuning uses a
40-iteration, 5-fold stratified randomized search scored on F1. The decision threshold is then chosen
on the validation precision-recall curve, maximizing F1, instead of the default 0.5. We additionally
run 5-fold stratified cross-validation, refitting preprocessing, resampling, and the tuned
hyperparameters inside each fold, for a variance estimate beyond a single 1{,}000-row test split.
Test-set intervals are exact binomial (Clopper--Pearson) for precision and recall and a 5{,}000-sample
stratified bootstrap for F1 and the AUCs.

\subsection{XAI cross-checking protocol}
\label{sec:crosscheck}
This is the core methodological contribution. We compute SHAP \texttt{TreeExplainer} values for the
final tuned model on all flagged rows (not just the test split -- TWF and RNF have under 50 rows in
total, too few to analyze within a 1{,}000-row test partition; this uses no training signal, only
post-hoc explanation of an already-fixed model). For mechanism $m$ and feature $j$,
\[
  I_{m,j} = \frac{1}{|S_m|} \sum_{i \in S_m} \left| \phi_j(x_i) \right|,
\]
where $S_m$ is the set of rows for which $m$ fired and $\phi_j(x_i)$ is the SHAP value of feature $j$
for row $i$. Let $E_m$ be the features $m$'s trigger depends on (raw inputs and their derived
versions): TWF -- tool wear; HDF -- air and process temperature, their difference, rotational
speed; PWF -- torque, rotational speed, power; OSF -- tool wear, torque, overstrain, overstrain
ratio. The audit statistic is the \emph{relevant share}
\[
  R_m = \sum_{j \in E_m} I_{m,j} \Big/ \sum_j I_{m,j}.
\]

\paragraph{Why a naive null fails.} The obvious test compares $R_m$ against the same statistic on
random, equally sized subsets of failure rows under the same model. This is confounded: rows where
$m$ fired are, by definition, extreme in the features of $E_m$, and $|\phi_j|$ tends to be large at
extreme feature values even for a model that learned nothing useful. A model trained on permuted
labels passes this naive test on every mechanism (Section~\ref{sec:robustness}).

\paragraph{Model-randomization null.} Following \citet{adebayo2018sanity}, we instead retrain the
identical pipeline (same features, resampling, and hyperparameters) $K = 100$ times on permuted
training labels and compute $R_m$ for each. A mechanism passes if the real model's $R_m$ exceeds the
permuted models' with $p = (1 + \#\{R^{\text{perm}}_m \ge R_m\})/(K+1) < 0.05$; the smallest
attainable $p$ is $1/101 \approx 0.0099$. For RNF, which has no cause, the statistic is the share of
the single top feature, and RNF passes if the real model is \emph{not} more concentrated on RNF rows
than the permuted models ($p \ge 0.05$).

\subsection{Can the audit fail? Controls and ablation}
\label{sec:robustness}
Table~\ref{tab:robustness} runs the same audit, each with its own 100-model randomization null,
on five variants of the pipeline.

\paragraph{Label permutation.} A model trained on shuffled labels (test F1 0.08) fails all four
physical mechanisms. The naive null from Section~\ref{sec:crosscheck} passes this same model on all
four ($p = 0.0005$ each), which is the concrete reason we reject it.

\paragraph{Spurious shortcut.} We add a synthetic ``sensor'' with no physical role that tracks HDF,
at two strengths. With a weak, noisy signal ($\mathcal{N}(0,1) + 1.5\,\text{HDF}$) the model ignores
it -- the true HDF features already determine HDF exactly -- and the audit correctly passes every
mechanism. With a strong signal ($\mathcal{N}(0,0.1) + \text{HDF}$) the model routes HDF through the
shortcut: HDF's top feature becomes the fake sensor and $R_{\text{HDF}}$ collapses from 0.705 to
0.156, a clear fail, while TWF, PWF and OSF still pass. The audit localizes the fault to the one
mechanism the shortcut mimics. This model's test F1 is 0.86 -- below the tuned model but above every
non-XGBoost baseline in Table~\ref{tab:models} -- so accuracy alone would not have flagged it.

\paragraph{Raw features only.} To address the concern that engineered features built from the
trigger rules make the audit circular, we retrain without them. Test F1 drops from 0.90 to 0.84.
TWF, PWF and OSF still pass clearly ($p = 0.0099$), with the expected raw drivers on top (torque for

\emph{difference} of two temperatures, which a tree ensemble on raw inputs must approximate, and a
know-nothing model already places much of its attribution on those same three features (null mean
0.60). The audit therefore has low power for difference-based mechanisms unless the relevant
quantity is available as a feature.

\section{Discussion}

\subsection{What the controls show}
The strong-shortcut model is the case the audit exists for: it scores competitively on held-out
data, yet it is wrong about \emph{why} one class of failure happens. Only the per-mechanism view exposes it, and it does so selectively -- the other
three mechanisms still pass. The permuted-label result makes a second, methodological point: an
attribution audit whose null does not account for how atypical the audited rows are will certify
models that learned nothing. We expect this confound to apply to any subgroup-level attribution
analysis, not only this one.

\subsection{Limitations}
\label{sec:limitations}
AI4I~2020 is a synthetic dataset generated from the same closed-form rules used as our ground truth
(Table~\ref{tab:mechanisms}); the ``ground truth'' is therefore the simulator's logic, not an
independently verified physical measurement from real equipment. This is a genuine limitation for
any claim that the protocol validates \emph{real-world} causal faithfulness, and we do not make that
claim here -- our contribution is the protocol and its demonstration, not a validated causal
finding about real machinery. This concern is not merely theoretical: \citet{autran2024ai4ipmdi}
show that injecting realistic irregularities (missing data, irregular time-series sampling) into
AI4I~2020 measurably changes downstream model performance, underscoring that results on the clean
synthetic version -- ours included -- may not transfer directly to messier real deployments.

Several further limitations are specific to the audit. The RNF check is weak: 18 of its 19 rows are
non-failures, so it mainly shows the model does not concentrate attribution on arbitrary rows; the
discriminating evidence comes from the permutation and shortcut controls. TWF (46 rows) is small,
and its trigger is partly random, so its $R$ is low in absolute terms even when it passes. With
$K = 100$ permuted models the smallest attainable $p$ is 0.0099, so several verdicts sit at that
floor and more permutations would sharpen them. The audit has low power for mechanisms defined by a
difference or ratio of raw inputs unless that quantity is a feature (HDF in the raw-feature
ablation). We audit one model family (XGBoost) with one explainer (TreeSHAP); whether the null's
behaviour carries over to other explainers is untested. Finally, the audit requires sub-labels for
at least some failures -- available here by construction, and in industrial settings where
maintenance logs record a root cause, but not universal.

\subsection{Generalizability}
The protocol requires only two things: (1) a classifier trained on a coarse target, and (2) a
held-out set of finer-grained sub-labels for at least some of the positive cases, not used in
training. Both hold wherever maintenance records log a root-cause code for failures that a deployed
model predicts only as a binary risk; we have not measured how widespread such records are. Where
they exist, this protocol offers a cheap, dataset-native alternative to constructing synthetic
ground-truth benchmarks purely to evaluate explanation faithfulness.

\section{Conclusion}
We show that AI4I~2020's five failure mechanisms, ordinarily discarded once the composite failure
label is formed, can be repurposed as a faithfulness probe for post-hoc SHAP explanations. With a
model-randomization null, a tuned XGBoost classifier trained only on the composite label passes all
four physical mechanisms, a label-permuted model fails all four, and a model given a spurious
shortcut fails exactly the mechanism the shortcut mimics while its accuracy stays competitive. Along
the way we find that the obvious null for this kind of subgroup audit is confounded and certifies a
model that learned nothing. We position the protocol as a low-cost check applicable wherever a
coarse PdM target aggregates several distinct, partially-labeled failure modes -- a complement to,
not a replacement for, faithfulness evaluation on purpose-built synthetic data.
