\title{Auditing SHAP Explanations Against Latent Failure Mechanisms in Predictive Maintenance}

\author{\IEEEauthorblockN{Koshik Debanath}
\IEEEauthorblockA{Independent Researcher\\
koshik.debanath@gmail.com}}

\maketitle

\begin{abstract}
% X: what and why
Analysts use SHAP (SHapley Additive exPlanations) to explain predictive maintenance (PdM)
classifiers, but rarely test whether an explanation matches the physical cause of failure.
% Y: why hard
Such a test needs ground truth about why each failure happened, which PdM data rarely provides, and
we show that an obvious test for it certifies a model fitted to shuffled labels.
% Z: what we do
We use the AI4I~2020 dataset, whose failure label is the logical OR of separately recorded failure
mechanisms. We train a classifier on the combined label only, compute out-of-sample SHAP values by
cross-fitting, and test two statistics per mechanism against 1{,}000 models retrained on permuted
labels: the share of attribution on the mechanism's trigger features, and how much larger that
share is on the mechanism's rows than on other failures.
% 1: evidence
With Holm correction, the tuned XGBoost model (test F1 0.89) passes both tests for heat
dissipation, power, and overstrain failure in all five seeds (adjusted $p \le 0.02$), but not for
tool wear failure, which passes only when SHAP is computed on training rows. Without the features
derived from the trigger rules, power and overstrain still pass both tests and heat dissipation
passes one. A graded shortcut experiment shows that the audit flags a synthetic sensor once it
carries about a fifth of the attribution on the affected mechanism's rows, but not at 13\%, while
test F1 stays between 0.84 and 0.92. On re-simulations of up to 300{,}000 rows, the permutation test
gains power for true mechanisms but stops flagging a shortcut that carries 28\% of the attribution,
so the attribution share itself, not only its $p$-value, has to be reported.
\end{abstract}

explainable AI, SHAP, predictive maintenance, faithfulness evaluation, model randomization,

\section{Introduction}
\label{sec:intro}

% X: explanations of PdM models are trusted without being tested against the true cause
Predictive maintenance (PdM) systems predict equipment failure from sensor readings of
cyber-physical systems, where a wrong reason for a correct alarm can send a technician to the wrong
component. Users typically explain these models with post-hoc attributions such as
SHAP~\cite{lundberg2017shap} and read the result as evidence that the model relies on sensible
inputs~\cite{vollert2021interpretable,cummins2024survey}. The explanation itself is rarely tested
against the actual cause of failure: a classifier with high accuracy can still rely on a correlate of
failure, a shortcut~\cite{geirhos2020shortcut,lapuschkin2019unmasking}, and a plausible SHAP plot
does not reveal this.

% Y: needs per-failure causes; naive tests are confounded
Testing an explanation against causes requires knowing, for each failure, which mechanism produced
it, and industrial datasets seldom record this. A second difficulty is statistical. Rows that belong
to a failure mechanism are extreme in that mechanism's features, and we find that a test which
ignores this effect passes a model fitted to shuffled labels (\cref{sec:robust}).

% Z: AI4I records mechanisms separately; we audit against them
The AI4I~2020 dataset~\cite{matzka2020explainable} records the mechanism of each failure. Its
target, \texttt{Machine failure}, is the logical OR of five flags: tool wear failure (TWF), heat
dissipation failure (HDF), power failure (PWF), overstrain failure (OSF), and random failure (RNF).
The first four follow published trigger rules on the sensor variables (\cref{tab:mechanisms}); RNF
does not. We train on the combined label only and keep the flags for an audit. For each mechanism,
we measure how much of the model's out-of-sample SHAP attribution falls on the features its trigger
rule uses, and whether that concentration is specific to its own rows, against models retrained on
permuted labels~\cite{adebayo2018sanity}.

% 1: hypotheses and outcomes
We test three hypotheses:
\begin{itemize}
  \item \textbf{H1:} for each physical mechanism, the model's attribution concentrates on the
    trigger features (1) more than permuted-label models do and (2) more on that mechanism's rows
    than on other failures;
  \item \textbf{H2:} the audit flags a model that relies on a shortcut sensor for the mechanism the
    shortcut imitates, while mechanisms that passed before keep passing;
  \item \textbf{H3:} a naive null, which compares random failure rows under the same model, does not
    separate a trained model from a permuted-label one.
\end{itemize}
H1 holds for HDF, PWF, and OSF but not for TWF (\cref{fig:overview}), whose verdict also depends on
the SHAP variant; H2 holds on the released data once the shortcut carries about a fifth of the
attribution, but not on a 300{,}000-row re-simulation; H3 holds.

% 2: contributions, separated from prior work
Our contributions are:
\begin{itemize}
  \item a per-mechanism SHAP audit with two statistics, out-of-sample attributions, a
    model-randomization null, and multiple-comparison correction (\cref{sec:method});
  \item evidence that a naive within-model null is confounded (\cref{sec:robust});
  \item a graded shortcut experiment that measures when the audit detects reliance on a spurious
    sensor (\cref{sec:sweep}), plus seed, single-mechanism, in-sample, raw-feature, explainer, and
    model-family analyses;
  \item a scaling study on AI4I~2020 re-simulated at up to $10^6$ rows, which shows how the test's
    power and cost change with data size and where the permutation test alone stops detecting a
    shortcut (\cref{sec:scale});
  \item an imbalance-aware benchmark of seven model families on AI4I~2020 with confidence
    intervals, and a code base that regenerates every number, table, and figure.
\end{itemize}
The resampling methods, models, explainer, and randomization idea are existing tools; the audit
statistics, the null analysis, and the controls are ours.

\section{Related Work}
\label{sec:related}

% XAI on AI4I: global reporting, no mechanism-level test; we compare predictive results
\textit{Explanations on AI4I~2020.} Matzka~\cite{matzka2020explainable} introduced the dataset with
local explanations of individual predictions, and Zhao et al.~\cite{milling2025shap} report global
SHAP importance for tree ensembles on it. Neither tests attributions against the mechanism flags or
defines a pass/fail criterion, so there is no audit to compare against. For predictive performance,
Su and Tseng~\cite{physicsinformed2026} report random forest positive-class F1 of 0.722 on the binary label with
engineered physics-informed features
(\cref{tab:prior}). Khemani and Qureshi~\cite{connectedvehicles2026} report LightGBM macro-F1 of
$0.814 \pm 0.012$ over the failure-mode classes from raw features; that task differs from ours, so we
do not compare numbers with it.

% Ground-truth attribution benchmarks evaluate explainers; we evaluate models
\textit{Evaluating attributions against ground truth.} A line of work tests explainers on data where
the important features are known by construction: XAI-Bench~\cite{liu2021synthetic} and
OpenXAI~\cite{agarwal2022openxai} generate synthetic tabular data, BAM~\cite{yang2019bam} and Zhou
et al.~\cite{zhou2022attribute} modify images or text so that a known feature drives the label, and
CLEVR-XAI~\cite{arras2022clevr} provides ground-truth masks for visual questions.
ROAR~\cite{hooker2019roar} and ROAD~\cite{rong2022road} avoid ground truth by removing the
features an explainer ranks highest and measuring the change in performance. These methods ask whether an explainer reports what the model uses. We ask
the complementary question: given TreeSHAP, whose values are exact for tree ensembles~\cite{lundberg2020treeshap}, does the
model use what the data-generating mechanism uses? The benchmarks above control the data-generating
process, which AI4I~2020 does not expose beyond its trigger rules, so we do not run them as
baselines. Chen et al.~\cite{chen2020true} distinguish attributions that are ``true to the model''
from ones ``true to the data''; our audit targets the second property at the level of mechanism
subgroups.

% Randomization tests: adopted, applied to the model
\textit{Randomization tests.} Permuted-label retraining is an established null for classifier
performance~\cite{ojala2010permutation} and for feature importance: Altmann et
al.~\cite{altmann2010permutation} retrain on permuted labels to obtain null importances per feature.
Adebayo et al.~\cite{adebayo2018sanity} use model randomization to show that some saliency methods
give nearly the same explanation for a trained model and a randomized one, and later work questions
what such checks can establish~\cite{kindermans2019unreliability,yona2021revisiting}. We use the
permuted-label null of Altmann et al., but for a different statistic: attribution shares on
mechanism subgroups rather than global importance of single features.

\textit{Limits of SHAP.} Shapley-value attributions depend on how absent features are
modeled~\cite{janzing2020feature,kumar2020problems}; with dependent features, as our derived features
are, the observational and interventional variants can differ~\cite{aas2021explaining}, and
explanations can be manipulated~\cite{slack2020fooling}. We therefore repeat the audit with
interventional TreeSHAP (\cref{sec:variants}).

% Causal PdM: different goal
\textit{Causal PdM.} Dhande et al.~\cite{causalbenchmark2026} compare a Bayesian structural causal
model with correlational models on 10{,}000 CNC records with 3.3\% failures, which matches
AI4I~2020, and report that the causal model attributes HDF, PWF, and OSF failures correctly. They
replace the correlational model with a causal one; we keep the kind of correlational model that dominates
PdM work~\cite{serradilla2022deep} and test its explanation.

\section{Background and Problem Setting}
\label{sec:background}

% SHAP basics
\textit{SHAP.} For a model $f$ and input $x$ with $d$ features, SHAP assigns each feature $j$ an
attribution $\phi_j(x)$, its Shapley value with respect to the model output, such that
$f(x) = \phi_0 + \sum_{j=1}^{d} \phi_j(x)$, where $\phi_0$ is the expected
output~\cite{lundberg2017shap}. TreeSHAP computes these values exactly for tree
ensembles~\cite{lundberg2020treeshap}; by default it follows the tree paths (path-dependent), and an
interventional variant averages over a background sample instead. We use
$|\phi_j(x)|$ as the magnitude of feature $j$'s contribution to the prediction for $x$.

% Problem setting and notation
\textit{Problem setting.} We observe rows $(x_i, y_i, z_i)$, where $x_i$ is the sensor vector,
$y_i \in \{0, 1\}$ the failure label, and $z_i \in \{0, 1\}^M$ holds $M$ mechanism flags. We train
$f$ on $(x_i, y_i)$ only. For each mechanism $m$, domain rules give a set $E_m$ of features the
mechanism's trigger depends on. With $S_m = \{i : z_{i,m} = 1\}$ and $F = \{i : y_i = 1\}$, the
audit asks whether attributions on $S_m$ concentrate on $E_m$, and more so than on $F \setminus S_m$.
Two assumptions are unusual: $E_m$ must be known, and the flags must exist for some failures even
though the model never sees them.

\section{Audit Method}
\label{sec:method}

% Statistics
For a set of rows $S$ and mechanism $m$, let
$I_{m,j}(S) = |S|^{-1} \sum_{i \in S} |\phi_j(x_i)|$ and define the share of attribution on the
trigger features,
\begin{equation}
  r_m(S) = \sum_{j \in E_m} I_{m,j}(S) \Big/ \sum_{j=1}^{d} I_{m,j}(S).
\end{equation}
The audit uses two statistics, the \textit{relevant share} and the \textit{specificity},
\begin{align}
  R_m &= r_m(S_m), \label{eq:share} \\
  D_m &= r_m(S_m) - r_m(F \setminus S_m). \label{eq:spec}
\end{align}
$R_m$ is large when attribution on the mechanism's rows falls on its trigger features; $D_m$ is
large when this concentration is specific to those rows rather than common to all failures.

% Out-of-sample attributions
\textit{Out-of-sample attributions.} Attributions on training rows reflect what the model fitted,
not what it generalizes. We therefore cross-fit~\cite{chernozhukov2018double}: we split the data into five stratified folds, train
the full pipeline on four, and compute SHAP values for the held-out fold, so that every audited row
is explained by a model that never saw it.

% Naive null and its confound
\textit{Naive null.} An obvious test compares $R_m$ with the same statistic on random, equally sized
subsets of $F$ under the same model. It passes a model fitted to shuffled labels
(\cref{sec:robust}). A likely reason is that rows in $S_m$ are extreme in the features of $E_m$,
because the trigger rule selects them by those features, and $|\phi_j|$ tends to be larger at
atypical feature values whatever the model has fitted.

% Model-randomization null, p-values, correction
\textit{Model-randomization null.} We rerun the full procedure -- features, resampling, fitting,
and cross-fitting -- $K$ times on permuted labels and compute both statistics for each run. The
hyperparameters stay at the values tuned on the real labels, so the null runs differ from the audited
model only in the labels. For $T \in \{R_m, D_m\}$ with null values $T^{(k)}$,
\begin{equation}
  p = \frac{1 + \#\{k : T^{(k)} \ge T\}}{K + 1},
\end{equation}
and we adjust the four physical mechanisms for multiple comparisons with Holm's method~\cite{holm1979simple}, separately
for each statistic. A mechanism passes a test if its adjusted $p$ is below 0.05.

% RNF
\textit{Random failures.} RNF has no trigger features. We report the share of its single largest
feature and whether it is more concentrated than under the null, as a descriptive check rather
than a pass/fail test.

\section{Experimental Setup}
\label{sec:setup}

% Dataset and label inconsistencies
\textit{Dataset.} AI4I~2020 has 10{,}000 rows: a quality variant \texttt{Type} $\in \{L, M, H\}$,
five process variables (air and process temperature, rotational speed, torque, tool wear), the
failure label, and the five mechanism flags. 339 rows (3.39\%) are failures. The labels depart from
the stated OR rule: 24 rows carry several mechanism flags, 9 failures carry none, and 18 of the 19
RNF rows have \texttt{Machine failure}~$= 0$, which is why we treat RNF descriptively. We audit all
flagged rows and, separately, rows with exactly one flag.

% Features
\textit{Features.} We derive four features from the trigger rules without using the flags:
\textit{power} (torque $\times$ speed), \textit{temperature difference} (process $-$ air),
\textit{overstrain} (tool wear $\times$ torque), and \textit{overstrain ratio} (overstrain over the
type-specific limit). The mechanism flags are components of the label, so we exclude them from the
features.

% Training
\textit{Training.} We split the data 70/20/10 into training, validation, and test sets, stratified by
label, and fit scaling and one-hot encoding on the training set. We compare three oversamplers -- the synthetic minority
oversampling technique (SMOTE)~\cite{chawla2002smote}, Borderline-SMOTE~\cite{han2005borderline}, and
ADASYN~\cite{he2008adasyn} -- by the validation F1 of a default XGBoost~\cite{chen2016xgboost} model
and use the best, Borderline-SMOTE (\cref{tab:resamplers}). We train seven model families: logistic regression, a support vector machine (SVM),
$k$-nearest neighbors ($k$-NN), a decision tree, a random forest, XGBoost, and a multilayer
perceptron (MLP) (\cref{tab:config}; the tuned XGBoost is the eighth row, not a separate family).

% Selection, tuning, uncertainty
\textit{Selection and tuning.} We select on the validation set only: XGBoost has the highest
validation F1, so we tune it with a 40-iteration randomized search under 5-fold stratified
cross-validation, scored on F1, with Borderline-SMOTE inside the pipeline so that each fold
resamples only its own training part, over depth 3--8, 200--600 trees, learning rate 0.01--0.2,
subsample and column sample 0.6--1.0, minimum child weight 1--5, and $\gamma$ 0--0.3. We set the
decision threshold to maximize F1 on the validation precision-recall (PR) curve. Confidence intervals
(CIs) are exact binomial (Clopper--Pearson) for precision and recall and a 5{,}000-sample stratified
bootstrap otherwise. We also run 5-fold stratified cross-validation of the whole pipeline at the
default threshold of 0.5.

% Audit configuration and cost
\textit{Audit.} The primary audit cross-fits the tuned pipeline with seed 42 and $K = 1{,}000$
permuted-label runs, so the smallest attainable $p$ before correction is 0.001. We repeat it with
seeds 1--4 ($K = 200$), with raw features only ($K = 1{,}000$; without the four derived features,
to test whether they make the audit circular), and with SHAP from a single model fitted on all rows
and explaining those same rows (\textit{in-sample}, $K = 1{,}000$). Each cross-fitted run costs
$5(K+1)$ model fits; the runs are independent, and the primary audit takes 11 minutes on eight CPU
cores.

% Controls
\textit{Explainer and model variants.} We repeat the primary audit ($K = 200$) with interventional
TreeSHAP, using a background of 100 training rows per fold, and with the random forest of
\cref{tab:config} in place of XGBoost; in both, the null runs use the same explainer and model.

\textit{Scaling.} To study larger data, we re-simulate AI4I~2020 at $n \in \{10^4, 3 \cdot 10^4,
10^5, 3 \cdot 10^5\}$ rows: we draw the five process variables jointly from the released rows with
small Gaussian jitter and recompute the flags from the published trigger rules, which reproduce the
released HDF, PWF, and OSF flags exactly. TWF is random in the original simulator, so we draw it with
the released rate among worn tools; RNF fires with probability 0.001. Unlike the release, the
simulated labels are consistent. At each size we run the audit without the shortcut sensor and with
it at $\sigma \in \{0.5, 0.35, 0.25\}$ ($K = 100$, smallest adjusted $p$ 0.040), and we time one
cross-fitted run at $10^6$ rows.

\textit{Controls.} A model trained on permuted labels is exchangeable with the null runs, so its
$p$-values are uniform by construction; we use it only as a sanity check of the code and as the
case that the naive null must fail. For H2, we add a synthetic ``sensor''
$s = z_{\mathrm{HDF}} + \mathcal{N}(0, \sigma^2)$ with no physical role and vary $\sigma$ from 2 to
0.1. For each $\sigma$ we report the sensor's share of attribution on HDF rows, test F1, and the
audit verdicts ($K = 500$). The sensor is not in $E_{\mathrm{HDF}}$, so a model that relies on it
should fail the HDF audit.

\subsection{Audit of the tuned model (H1)}
\label{sec:audit-results}

% H1 supported for HDF, PWF, OSF
For HDF, PWF, and OSF the tuned model passes both tests (\cref{tab:audit}, \cref{fig:overview}). On
each mechanism's held-out rows, the share of attribution on its trigger features exceeds that of
every permuted-label run, and it exceeds the share on other failures by 0.33 to 0.43, against
null means below 0.09. The highest-attribution feature is a trigger feature in each case.
\Cref{fig:shap}a shows the attribution matrix.

% H1 not supported for TWF
TWF fails both tests ($p = 0.201$ and $0.077$). Tool wear is its highest-attribution feature, but it
takes only 19\% of the attribution on TWF rows, against 15\% under the null. The TWF trigger fires
at a random point within a tool-wear window, so tool wear only partly determines it, and the 46 TWF
rows give little to generalize from.

\subsection{Robustness (H1, H3)}
\label{sec:robust}

% Seeds, single rows
\Cref{tab:robust} repeats the audit. The HDF, PWF, and OSF verdicts hold in all five seeds and on
single-mechanism rows. TWF fails both tests in every seed.

% In-sample optimism
With SHAP from a model that has seen every audited row, all four mechanisms pass, including TWF
($p = 0.004$; $R_{\mathrm{TWF}} = 0.35$ against 0.19 out-of-sample). The
difference from the cross-fitted result shows that in-sample attributions can overstate how well a
model's explanation matches a mechanism.

% Raw features: circularity partly addressed
Without the derived features, PWF and OSF pass both tests (OSF specificity narrowly, $p = 0.048$),
HDF passes only on specificity, and TWF on neither. The derived features therefore help the HDF
verdict but are not needed for PWF and OSF: the audit is not circular for those two, and a mechanism
defined by a difference of inputs, as HDF is, is harder to audit when the model must approximate the
difference with splits.

% H3 and sanity
The permuted-label model fails every test under the model-randomization null, as it must. The naive
null passes it on all four mechanisms (Holm-adjusted $p = 0.002$), exactly as it passes the tuned
model, including on TWF, which the model-randomization null rejects. The naive null therefore does
not separate the two models, which supports H3.

% Detection threshold
\Cref{tab:sweep,fig:sweep} show the shortcut sweep. For $\sigma \ge 0.4$ the sensor receives at most
8\% of the attribution on HDF rows and the audit passes, which is correct because the model barely
uses it. At $\sigma = 0.35$ the sensor takes 13\% and the relevant-share test passes narrowly
($p = 0.044$). From $\sigma = 0.3$, where the sensor takes 21\%, the HDF relevant-share test fails,
and from $\sigma = 0.2$ (43\%) the specificity test fails as well. Test F1 stays between 0.84 and
0.92 across the sweep, so accuracy does not reveal the shortcut. H2 therefore holds once a shortcut
takes about a fifth of the attribution, not for lighter reliance. PWF and OSF pass at every noise
level, and TWF fails at every level, as in the primary audit.

\subsection{Explainer and model variants}
\label{sec:variants}

% HDF/PWF/OSF robust; TWF depends on the SHAP variant
The HDF, PWF, and OSF verdicts hold with interventional TreeSHAP and with a random forest
(\cref{tab:robust}). TWF does not behave consistently: it passes both tests with interventional
TreeSHAP ($R_{\mathrm{TWF}} = 0.45$, tool wear its top feature) and fails both with the random forest
($R_{\mathrm{TWF}} = 0.13$, speed its top feature). Path-dependent TreeSHAP spreads credit over
features correlated with those a tree splits on, and tool wear is correlated with the two overstrain
features, so the two variants can divide the TWF attribution differently~\cite{aas2021explaining}.
An audit verdict is therefore a statement about a model \emph{and} an explainer, and a mechanism
that passes under one explainer only should be reported as unresolved.

% Power grows for true mechanisms
With more data the audit gains power for true mechanisms (\cref{tab:scale}). Without the sensor, HDF, PWF, and OSF
pass both tests at every size, and TWF specificity, which fails on 10{,}000 rows, passes from 30{,}000;
TWF relevant share fails at every size, so its weak attribution is not a small-sample effect.

% But the p-value stops detecting the shortcut
The shortcut result does not scale the same way. With more data the model relies less on the sensor
at a fixed $\sigma$, but at $\sigma = 0.25$ it still gives the sensor 28--35\% of the HDF
attribution at every size. On up to 100{,}000 rows the relevant-share test flags this; on 300{,}000
rows it does not ($p = 0.040$), because the null concentrates as $n$ grows ($R_{\mathrm{HDF}}$ of
0.486 against a null mean of 0.359) while the shortcut still takes more than a quarter of the
attribution. The model-randomization null tests whether a model uses a mechanism's features more
than a model that learned nothing, not whether it uses them exclusively, and at scale that bar is
low. The attribution share itself does reveal the shortcut: $R_{\mathrm{HDF}}$ drops from 0.755
without the sensor to 0.486 with it. We therefore report $R_m$ and $D_m$ as effect sizes next to
their $p$-values, and read a pass as ``better than chance'' rather than ``free of shortcuts''.

% Cost
Cost grows with $n$ and $K$: one audit with $K = 100$ takes 1 minute at 10{,}000 rows and 23 minutes
at 300{,}000 on eight cores, and one cross-fitted run at $10^6$ rows (34{,}285 failures) takes
93\,s on one core, so $K = 1{,}000$ at that size needs at least 3 hours on eight cores. The null runs
are independent and parallelize across machines.

% Resampling effect
Borderline-SMOTE has the highest validation F1 (\cref{tab:resamplers}). \Cref{fig:boundary} shows its

resampling the decision boundary barely reaches the failure class, and each oversampler moves it

\Cref{fig:dimred} projects the training data with PCA, t-distributed stochastic neighbor embedding

(UMAP)~\cite{mcinnes2018umap}. The classes overlap in the linear projection, consistent with the low
F1 of the linear models, while failures form several separate groups in the nonlinear ones,
consistent with several distinct mechanisms. The groups persist at t-SNE perplexities from 5 to
100 (repository figure), which matters because t-SNE shapes depend on
perplexity~\cite{wattenberg2016misread}.

\subsection{Limitations}
\label{sec:limits}

% Synthetic ground truth
AI4I~2020 is simulated from the same rules we use as ground truth, so the audit checks agreement
with the simulator's logic, not with independent measurements of real machines; we contribute a
protocol, not a finding about real equipment. Autran et al.~\cite{autran2024ai4ipmdi} show that
realistic irregularities added to AI4I~2020 change model performance, so results on the clean data
may not transfer.

% Audit-specific
The permutation test detects reliance on a shortcut from about a fifth of the attribution on the
released data but not below, and on large data not even at a quarter, so its $p$-value must be read
with the effect size. The audit needs the trigger features
$E_m$ to be known, and the derived features influence its outcomes. We audit two model families and two
explainers on one simulator, released at 10{,}000 rows and re-simulated at up to $10^6$; mechanisms
with few rows, such as TWF and RNF, give weak evidence either way.

\section{Conclusion}
\label{sec:conclusion}

% Recap
We audited SHAP explanations of a PdM classifier against failure mechanisms that the model never
saw. With out-of-sample attributions, a model-randomization null, and Holm correction, the tuned
model's explanations match the heat dissipation, power, and overstrain mechanisms in all five seeds,
but not tool wear failure, which passes only when SHAP is computed on training rows. The audit flags
a shortcut sensor once it carries about a fifth of the attribution, while accuracy stays unchanged,
but on 300{,}000 re-simulated rows its $p$-value no longer does, and only the drop in the attribution
share shows the shortcut. The tool wear verdict changes with the SHAP variant.
A naive null that compares random failure rows under the same model passes a permuted-label model,
so subgroup attribution tests need a null that accounts for how atypical the audited rows are.

% Future work
The audit applies wherever maintenance records log a root cause for failures that a model predicts
as a binary risk; we have not measured how common such records are. Next steps are real maintenance
logs with recorded root causes, process data with labeled fault types such as the extended Tennessee
Eastman simulation~\cite{rieth2017tepdata,rieth2018issues}, a null with an effect-size margin so that
a pass also bounds reliance on shortcuts, and a formal power analysis of the shortcut threshold.
