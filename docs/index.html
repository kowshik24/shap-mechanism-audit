Abstract

Machine learning models predict equipment failures in industrial systems, but whether their explanations reflect the physical failure mechanism is rarely tested statistically. We propose a statistical audit that checks, for each documented failure mechanism, whether held-out SHAP attributions concentrate on the features named in that mechanism's rule. The audit uses three statistics, which measure the share of attribution on these features, how much larger this share is than on other failures, and how much any other feature gains. Each statistic is compared with pipelines retrained on shuffled labels. On the AI4I 2020 benchmark, a tuned XGBoost classifier (test F1 = 0.89) passes the audit for three of four physical mechanisms. The tool-wear result depends on the reference distribution of the explanation. It fails with path-dependent TreeSHAP and passes when attributions are measured against normal operation. A planted shortcut sensor shows that accuracy can stay high while attribution moves to a misleading feature, and that weak shortcuts, or shortcuts spread over several sensors, go undetected. On laboratory bearing recordings and simulated Tennessee Eastman process data, the audit finds attribution consistent with the specified features for inner- and outer-race faults and a reactor-cooling fault, and it flags an injected acquisition-gain shortcut although classification accuracy remains perfect. A passing audit is evidence about where attribution falls under a given mechanism map. It does not certify that the model is physically correct, and flagged features need to be investigated.

Contributions

  • A mechanism-level audit with three attribution statistics computed on held-out explanations, a retrained shuffled-label reference, and a decision rule that labels each mechanism as aligned, flagged, or not aligned for a stated configuration.
  • A study of the audit's behaviour in controlled experiments: leaving out held-out explanations or the retrained reference led to misleading passes, a planted sensor went undetected when weak and was detected when stronger, and the tool-wear result changed with the attribution reference.
  • Applications to AI4I 2020, laboratory bearing recordings and simulated process data, with a supplement and a versioned computational snapshot.

Method

A classifier \(f\) is trained on the inputs \(x_i\) and the overall failure label \(y_i\) only. For each mechanism \(m\), domain knowledge fixes a set \(E_m\) of expected features before the audit. \(S_m\) are the mechanism-positive observations and \(F\) the observed failures. With \(\phi_j(x_i)\) the held-out SHAP attribution of feature \(j\), absolute attributions are averaged over a set \(A\) and normalized:

$$I_j(A)=\frac{1}{|A|}\sum_{i\in A}|\phi_j(x_i)|,\qquad s_j(A)=\frac{I_j(A)}{\sum_{k=1}^{d} I_k(A)},\qquad r_m(A)=\sum_{j\in E_m}s_j(A).$$

The three statistics are

$$R_m=r_m(S_m),\qquad D_m=r_m(S_m)-r_m(F\setminus S_m),\qquad C_m=\max_{j\notin E_m}\big[s_j(S_m)-s_j(F\setminus S_m)\big].$$

Relevant share \(R_m\)

The share of attribution on mechanism \(m\)'s observations that falls on its expected features.

Specificity \(D_m\)

How much larger that share is on the mechanism's observations than on all other failures.

Outside-set excess \(C_m\)

How much the feature outside \(E_m\) with the largest gain increases its share. A significant excess names a feature to inspect.

Mechanism observations have extreme sensor values that receive large attributions even from a model that has learned nothing. Each statistic is therefore compared with \(K\) pipelines in which the failure labels are permuted and preprocessing, oversampling, training, cross-fitting and explanation are all repeated. For an observed value \(T\) and null values \(T^{(1)},\dots,T^{(K)}\),

$$p=\frac{1+\sum_{k=1}^{K}\mathbb{I}\big(T^{(k)}\geq T\big)}{K+1}.$$

After Holm correction across the four physical mechanisms (\(\alpha=0.05\)), a mechanism is flagged if \(C_m\) is significant, aligned if \(R_m\) and \(D_m\) are both significant, and not aligned otherwise.

Why held-out explanations and a retrained null are needed

A classifier trained on shuffled labels fails the alignment tests. Compared with random failure observations instead, all four mechanisms appear significant, because mechanism observations have unusual sensor values that receive large attributions in any case. Explaining training observations is also too optimistic: in-sample SHAP passes all four mechanisms, including tool wear.

Robustness and the attribution reference

Each variant changes one part of the primary configuration and is compared with its own null. Seeds, single-mechanism observations and a null re-tuned on every permutation change nothing. Across five seeds \(R_m\) varies by at most 0.02. Removing the engineered features or using SMOTE removes HDF's relevant-share result, and removing each mechanism's most attributed trigger from \(E_m\) makes the audit flag the omitted feature.

Tool wear depends on the reference distribution

Tool-wear failure fails with path-dependent TreeSHAP but passes with interventional TreeSHAP for every background size and seed, and with every tested normal-operation reference. Path-dependent TreeSHAP weights tree paths by the cover of the oversampled training data, which is balanced between failures and non-failures. Against this reference, ordinary operating values look like evidence against failure, and they dominate the absolute attribution of tool-wear observations, which the model rarely detects (recall 0.07). For questions about abnormal operation, we recommend a stated normal-operation reference.

Detecting planted shortcuts

A sensor \(s_i=z_{i,\mathrm{HDF}}+\epsilon_i\), \(\epsilon_i\sim\mathcal{N}(0,\sigma^2)\), is a noisy copy of the heat-dissipation flag with no physical role. Weak shortcuts (\(\sigma\geq0.35\), at most 13% of HDF attribution) leave HDF aligned. A moderate one (\(\sigma=0.30\)) removes the alignment without naming a feature, and stronger ones (\(\sigma\leq0.25\), at least 35%) are flagged by the outside-set test, which names the sensor. Test F1 stays between 0.84 and 0.92 throughout. When the same signal is split over three sensors, they take 38% of the attribution together at \(\sigma=0.35\) but at most 14% each, and no feature is flagged until \(\sigma=0.25\).

Effect of sample size

On data generated from the documented AI4I process, the strong sensor is flagged in all ten runs, including at 300,000 observations, where the relevant-share test alone would pass. As the null narrows with more data, a model can beat the shuffled-label pipelines while relying heavily on a misleading feature, and only the outside-set test changes the result.

Bearing and process data

CWRU bearings. A random forest classifies the fault location of 36 laboratory recordings from 19 spectral features; \(E_m\) holds the spectral power around each fault's defect frequency. Inner- and outer-race attribution concentrates on the defect frequencies. When each recording's amplitude is scaled by a fault-dependent gain, every recording is still classified correctly, yet outer-race attribution moves to log-RMS and the outside-set test flags it.

Tennessee Eastman process. 400 simulated runs with a reactor (IDV4) or condenser (IDV5) cooling-water disturbance; \(E_m\) holds the three variables of the disturbed loop. IDV4 is aligned. IDV5 is flagged on the E-feed valve, which may be a downstream control response that the three-variable map does not cover; the data cannot separate this from a shortcut. A null that rotates each run's time-ordered labels gives the same verdicts.

Practical guidance and limitations

Recommended defaults

  • Fix \(E_m\) before the audit and explain only held-out observations.
  • Refit the full pipeline for \(K\geq200\) shuffled-label nulls (\(K\geq500\) when an adjusted \(p\) lies near \(\alpha\); with \(M\) mechanisms, \(K\geq M/\alpha\)).
  • Measure attributions against normal operation for questions about abnormal behaviour, and report the reference.
  • Call a mechanism aligned only when both \(R_m\) and \(D_m\) pass, and report effect sizes with every verdict.
  • Treat outside-set excesses below about 0.05 as exploratory, and inspect every flag.

Limitations

  • Results hold for a stated configuration and depend on the reference, the oversampler, engineered features, the model and explainer, and the expected sets.
  • A flag alone cannot tell a missing trigger, a downstream effect and a shortcut apart.
  • The outside-set test misses weak shortcuts and shortcuts spread over several sensors, and flags small excesses at large \(n\).
  • AI4I and TEP are simulated and CWRU uses laboratory faults, so the audit shows agreement with documented rules and physics, not with verified causes in operating plants.

Code and reproduction

The repository contains the audit library, the 24 numbered experiment stages with their stored results, the tuned model, and the LaTeX sources. Seeds are fixed, and tables and figures are generated from the stored results.

git clone https://github.com/kowshik24/shap-mechanism-audit.git
cd shap-mechanism-audit
pip install -r requirements.txt -e .
python experiments/02_audit.py --quick   # primary AI4I audit with a tiny null
./reproduce.sh                           # every stage, tables, figures and both PDFs
